# Configuration reference

qcom-ptool reads only the files and options named on its command line; nothing is
loaded implicitly. `make` passes each layout to the tool and reads the build
variables below from the command line or the environment.

## Partition layouts (.conf)

Each [`platforms/<board>/<storage>/partitions.conf`](https://github.com/devdocsorg/qcom-ptool/tree/docs/repository-documentation/platforms) holds one storage
device: exactly one `--disk` line, then one `--partition` line per partition in
disk order. Lines starting with `#` and blank lines are ignored. Values follow the
option after `=`; booleans accept `1`, `y`, `yes` or `true` in any case, and
anything else is false. [loaders/conf.py](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/qcom_ptool/loaders/conf.py) parses the format.

| `--disk` option | Purpose and type | When omitted | Example |
| --- | --- | --- | --- |
| `--type` | Storage class: `emmc`, `nvme`, `spinor` or `ufs`; `nand` is accepted but writes no XML. | No XML is written | `--type=ufs` |
| `--size` | Device size in bytes, recorded in the layout; not written to `partitions.xml`. | Empty | `--size=137438953472` |
| `--sector-size-in-bytes` | Sector size in bytes (`SECTOR_SIZE_IN_BYTES`). | `512` | `--sector-size-in-bytes=4096` |
| `--write-protect-boundary` | Write-protect alignment in KB; `0` disables it. | `65536` | `--write-protect-boundary=0` |
| `--grow-last-partition` | Flag: grow the last partition to the end of the device. | Not grown | `--grow-last-partition` |
| `--align-partitions` | Performance alignment boundary in bytes. | Aligned to 4 KB | `--align-partitions=4096` |

| `--partition` option | Purpose and type | When omitted | Example |
| --- | --- | --- | --- |
| `--lun`, `--phys-part` | LUN or physical partition index (integer); required for multi-LUN UFS. | `0` | `--lun=1` |
| `--name` | Partition label; required. | Empty label | `--name=efi` |
| `--size` | Size in bytes, or with a `K`, `M` or `G` suffix and optional `B`; required. | Empty size | `--size=524288KB` |
| `--type-guid` | Partition type GUID; required. | All-zero GUID | `--type-guid=C12A7328-F81F-11D2-BA4B-00A0C93EC93B` |
| `--filename` | Image written to the partition. | No image | `--filename=efi.bin` |
| `--attributes` | GPT attribute bits in hex; only bit 2 (bootable) and bit 60 (read-only) are used. | See the two rows below | `--attributes=1000000000000004` |
| `--bootable` | Legacy BIOS bootable flag (boolean); overrides `--attributes`. | `false` | `--bootable=yes` |
| `--readonly` | Read-only flag (boolean); overrides `--attributes`. | `true` | `--readonly=false` |
| `--priority` | A/B slot priority, 0 to 3. | Not set | `--priority=2` |
| `--tries-remaining` | A/B slot retry count, 0 to 7. | Not set | `--tries-remaining=6` |
| `--active`, `--successful`, `--unbootable` | A/B slot flags (boolean). | `false` | `--active=1` |
| `--sparse` | Marks the image as sparse in the rawprogram output (boolean). | `false` | `--sparse=true` |
| `--uniqueguid` | Fixed partition unique GUID. | Generated by ptool | `--uniqueguid=11111111-2222-3333-4444-555555555555` |

Layouts end each UFS LUN with a zero-size `last_parti` entry; `gen_udev_rules` skips
that name. `gen_partition -m name=image,...` replaces the filename of the named
partitions after the layout is read.

## Board files (YAML)

A board file in [platforms/boards/](https://github.com/devdocsorg/qcom-ptool/tree/docs/repository-documentation/platforms/boards) describes every storage of a
board. `make` builds each board into `platforms/<board>/<storage-id>/` and skips
the `.conf` files in those folders. The
[board schema](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/qcom_ptool/schema/board.schema.json) validates the file.

| Key | Purpose and type | When omitted | Example |
| --- | --- | --- | --- |
| `platform.name` | Board name (string), shown by `qcom-ptool show`. | No name | `glymur-crd` |
| `extends` | Base board to inherit, relative to `platforms/`. | No base | `boards/base.yaml` |
| `storage[].id` | Storage identifier and output folder name; required. | — | `nvme` |
| `storage[].type`, `size`, `sector-size`, `write-protect-boundary`, `grow-last-partition`, `align-partitions` | The `--disk` options above; `type` and `size` are required once resolved. | As for `--disk` | `sector-size: 4096` |
| `storage[].includes` | Shared partition lists under `platforms/_common/`, added before the storage's own partitions. | None | `[_common/boot.yaml]` |
| `storage[].partitions` | Partitions in disk order, using the `--partition` option names; `--uniqueguid` is `unique-guid`. Quote sizes and GUIDs. | None | `{name: efi, size: "524288KB", type-guid: "C12A7328-F81F-11D2-BA4B-00A0C93EC93B"}` |

Settings are resolved in this order, later ones winning: base board, derived board,
storage includes, then the `--hlos` and `--boot-fw` overlays in
`platforms/variants/<hlos|boot-fw>/<name>.yaml`. Storages merge by `id` and
partitions by `name`; nothing is removed. A single-storage YAML file with `disk` and
`partitions` keys can replace a `.conf` file; the
[partition schema](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/qcom_ptool/schema/partitions.schema.json) describes it, and
[include.schema.json](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/qcom_ptool/schema/include.schema.json) describes shared
partition lists.

## Contents templates

`gen_contents` copies a [contents.xml.in](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/platforms/qcs6490-rb3gen2/ufs/contents.xml.in)
template and changes only these elements; everything else, such as `product_info`,
passes through to the flashing tools unchanged.

| Element | What gen_contents does |
| --- | --- |
| `product_info/chipid` | The `storage_type` of the entry with `flavor="default"` is used for the GPT, rawprogram, and patch entries. |
| `builds_flat/build/build_id` | Added to every build with the `-b` value; empty when `-b` is omitted. |
| `download_file` in the `common` build | Replaced by one entry per partition with a filename, then `gpt_mainN.bin` and `gpt_backupN.bin` per LUN. |
| `partition_file`, `partition_patch_file` in the `common` build | Replaced by `rawprogramN.xml` and `patchN.xml` per LUN. |

## Build variables and environment

| Setting | Purpose and type | When unset | Example |
| --- | --- | --- | --- |
| `QCOM_PTOOL` (make) | Command the Makefile runs for each step; ptool runs inside each platform folder, so use a command on `PATH` or an absolute path. | `qcom-ptool` from `PATH` | `make all QCOM_PTOOL=$HOME/.local/bin/qcom-ptool` |
| `BUILD_ID` (make) | Text passed to `gen_contents -b`. | No build ID | `make all BUILD_ID=local-1` |
| `TOPDIR` (make) | Set to the current directory; no rule uses it. | — | — |
| `PTOOL_SEED` (environment) | Seed for ptool's random disk and partition GUIDs, making output reproducible. | Random GUIDs | `PTOOL_SEED=qcom-ptool-ci` |

[checksums.sha256](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/tests/integration/checksums.sha256) matches only output built
with `PTOOL_SEED=qcom-ptool-ci`. [.env.example](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/.env.example) lists the same
settings; nothing reads it.

## Data files

- [filesystem-partition-names.list](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/qcom_ptool/data/filesystem-partition-names.list):
  one partition name per line, `#` comments allowed. `gen_udev_rules` writes no raw
  rule for these names, so their filesystems are still probed.
- [55-qcom-raw-partitions-noblkid.rules.in](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/qcom_ptool/data/55-qcom-raw-partitions-noblkid.rules.in):
  udev rules template whose single `@QCOM_RAW_PARTITION_RULES@` line becomes one
  rule per raw partition name; its comments explain each rule.

## Package and tool settings

[pyproject.toml](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/pyproject.toml) follows the
[pyproject.toml specification](https://packaging.python.org/en/latest/specifications/pyproject-toml/).

| Setting | Local choice |
| --- | --- |
| `[build-system]` | Build with setuptools 64 or newer. |
| `[project]` | Package `qcom-ptool` 1.0.0, BSD-3-Clause with `LICENSE`, README as the long description, Python 3.8 or newer. |
| `dependencies` | `PyYAML>=5.1` and `jsonschema>=3.2`, for YAML layouts. |
| `optional-dependencies.test` | `pytest`, installed with `pip install .[test]`. |
| `[project.scripts]` | The `qcom-ptool` command runs `qcom_ptool.cli:main`. |
| `[tool.setuptools.*]` | Package `qcom_ptool*` with its JSON schemas and `data` files. |
| [`[tool.ruff]`](https://docs.astral.sh/ruff/settings/) | Python 3.8 syntax, 120-character lines, and the rule sets and exceptions commented beside them; `qcom_ptool` sorts as first-party. |
| [`[tool.mypy]`](https://mypy.readthedocs.io/en/stable/config_file.html) | Check as Python 3.9, warn on returning `Any`, check untyped function bodies except in `msp` and `ptool`, allow untyped definitions, ignore missing stubs, and do not warn about unused sections. |
| [`[tool.pytest.ini_options]`](https://docs.pytest.org/en/stable/reference/customize.html) | Run `tests/unit` with the checkout on `sys.path`. |

[degpt/Cargo.toml](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/degpt/Cargo.toml) builds the `degpt` crate (edition 2021)
with the `gpt` 3.1 and `uuid` 1.8 crates; `Cargo.lock` pins them.

## Repository settings

- [.github/workflows/build.yml](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/.github/workflows/build.yml): on pull requests and
  pushes to `main`, runs lint, unit tests, the platform build, integration and
  checksum checks, the checksum-manifest freshness check, and `cargo build`.
- [.github/workflows/quic-organization-repolinter.yml](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/.github/workflows/quic-organization-repolinter.yml):
  on every push and pull request, checks licence, README, and source-header rules.
- [.github/workflows/documentation.yml](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/.github/workflows/documentation.yml): on
  pull requests and pushes to `main`, runs the documentation `setup` and `check` targets.
- [.github/CODEOWNERS](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/.github/CODEOWNERS): its comment explains the default reviewers.
- [.gitignore](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/.gitignore) and [degpt/.gitignore](https://github.com/devdocsorg/qcom-ptool/blob/docs/repository-documentation/degpt/.gitignore): keep
  generated platform output, Python and Rust build output, and documentation caches
  out of Git.
