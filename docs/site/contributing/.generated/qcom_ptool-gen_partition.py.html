qcom_ptool.gen_partition.usage() → NoReturn¶

Print the gen_partition usage text and exit.

Raises:

SystemExit -- Always, with status 1.

Example: qcom-ptool gen_partition -h calls this function.

qcom_ptool.gen_partition.generate_multi_lun_xml(disk_params: qcom_ptool.spec.DiskParams, partitions: qcom_ptool.spec.PartitionsByLun, output_xml: str) → None¶

Write a ptool partition XML with one physical_partition per LUN.

Disk settings other than type and size become parser_instructions. LUNs are written in numeric order and LUNs without partitions are skipped.

Parameters:

  • disk_params -- Normalised --disk settings.

  • partitions -- Partition entries grouped by LUN or physical partition.

  • output_xml -- Path of the XML file to write.

Example: generate_multi_lun_xml(spec["disk"], spec["partitions"], "partitions.xml")

qcom_ptool.gen_partition.generate_partition_xml(disk_params: qcom_ptool.spec.DiskParams, partitions: qcom_ptool.spec.PartitionsByLun, output_xml: str) → None¶

Write the partition XML for a supported storage type.

emmc, nvme, spinor and ufs are written; any other type prints a message and writes nothing.

Parameters:

  • disk_params -- Normalised --disk settings, including type.

  • partitions -- Partition entries grouped by LUN or physical partition.

  • output_xml -- Path of the XML file to write.

Example: generate_partition_xml(spec["disk"], spec["partitions"], "partitions.xml")

qcom_ptool.gen_partition.main(argv: list[str] | None = None) → int¶

Generate partition XML from a .conf/YAML layout or a board file.

Parameters:

argv -- Command line including the program name; defaults to sys.argv.

Returns:

0 on success, or 1 when the input cannot be loaded or the outputs do not match the board's storages.

Raises:

SystemExit -- With status 1 for missing or conflicting options.

Example: main(["gen_partition", "-i", "partitions.conf", "-o", "partitions.xml"]) returns 0.

qcom_ptool.gen_partition._run_board(board_file: str, root: str | None, hlos: str | None, boot_fw: str | None, outputs: list[str], outdir: str | None, image_map: dict[str, str]) → int¶

Write one partition XML for each storage of a resolved board.

Parameters:

  • board_file -- Board YAML file.

  • root -- Platforms directory for extends, includes and variants, or None to derive it from board_file.

  • hlos -- HLOS variant name, or None.

  • boot_fw -- Boot firmware variant name, or None.

  • outputs -- Explicit output paths in storage order; empty to use outdir.

  • outdir -- Directory that receives <storage-id>/partitions.xml, or None for ..

  • image_map -- Partition name to image filename overrides.

Returns:

0 on success, or 1 when the board cannot be resolved or the output count differs.

Example: _run_board("platforms/boards/glymur-crd.yaml", None, None, None, [], "platforms/glymur-crd", {}) writes the NVMe and SPI-NOR XML files.
