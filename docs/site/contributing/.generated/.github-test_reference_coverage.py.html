.github/test_reference_coverage.py¶

Source

Check that every function has native documentation and a rendered reference entry.

Run from the repository root after make -f docs/source/Makefile html. Functions are discovered from the sources, independently of the extractors: Python with ast, Rust with tree-sitter, and shell code in scripts, workflow run values, and Makefile recipes with tree-sitter. Shell functions and unknown source formats fail with a request to configure an extractor.

Example: "qcom_ptool/ptool.py" in source_files() returns True.

test_reference_coverage.python_problems(path, text)¶

Report Python functions with incomplete docstrings or no rendered entry.

A docstring needs a purpose sentence, :param and a type for each parameter, :returns: and a type when a value is returned, and an Example:. Nested functions cannot be rendered, so only their docstrings are checked.

Parameters:

  • path (str) -- Repository-relative source path.

  • text (str) -- Source code.

Returns:

One message per problem.

Return type:

list[str]

Example: python_problems("x.py", "def f():\n    pass\n") reports a missing docstring.

test_reference_coverage.rust_problems(path, text)¶

Report Rust functions without a doc comment, an example, or a rendered entry.

Parameters:

  • path (str) -- Repository-relative source path.

  • text (str) -- Source code.

Returns:

One message per problem.

Return type:

list[str]

Example: rust_problems("degpt/src/lib.rs", "fn f() {}") reports a missing doc comment.

test_reference_coverage.shell_problems(where, code)¶

Report shell functions, which need a configured shdoc reference.

Parameters:

  • where (str) -- Location shown in messages.

  • code (str) -- Shell code.

Returns:

One message per function.

Return type:

list[str]

Example: shell_problems("run.sh", "f() { :; }") reports f.
