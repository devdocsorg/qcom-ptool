Configuration reference¶

qcom-ptool reads only the files and options named on its command line; nothing is loaded implicitly. make passes each layout to the tool and reads the build variables below from the command line or the environment.

Partition layouts (.conf)¶

Each platforms/<board>/<storage>/partitions.conf holds one storage device: exactly one --disk line, then one --partition line per partition in disk order. Lines starting with # and blank lines are ignored. Values follow the option after =; booleans accept 1, y, yes or true in any case, and anything else is false. loaders/conf.py parses the format.

Layouts end each UFS LUN with a zero-size last_parti entry; gen_udev_rules skips that name. gen_partition -m name=image,... replaces the filename of the named partitions after the layout is read.

Board files (YAML)¶

A board file in platforms/boards/ describes every storage of a board. make builds each board into platforms/<board>/<storage-id>/ and skips the .conf files in those folders. The board schema validates the file.

When omitted

No name

extends

Base board to inherit, relative to platforms/.

No base

storage[].id

Storage identifier and output folder name; required.

—

nvme

storage[].type, size, sector-size, write-protect-boundary, grow-last-partition, align-partitions

The --disk options above; type and size are required once resolved.

As for --disk

sector-size: 4096

storage[].includes

Shared partition lists under platforms/_common/, added before the storage's own partitions.

None

[_common/boot.yaml]

storage[].partitions

Partitions in disk order, using the --partition option names; --uniqueguid is unique-guid. Quote sizes and GUIDs.

None

{name: efi, size: "524288KB", type-guid: "C12A7328-F81F-11D2-BA4B-00A0C93EC93B"}

Settings are resolved in this order, later ones winning: base board, derived board, storage includes, then the --hlos and --boot-fw overlays in platforms/variants/<hlos|boot-fw>/<name>.yaml. Storages merge by id and partitions by name; nothing is removed. A single-storage YAML file with disk and partitions keys can replace a .conf file; the partition schema describes it, and include.schema.json describes shared partition lists.

Contents templates¶

gen_contents copies a contents.xml.in template and changes only these elements; everything else, such as product_info, passes through to the flashing tools unchanged.

Element

What gen_contents does

product_info/chipid

The storage_type of the entry with flavor="default" is used for the GPT, rawprogram, and patch entries.

builds_flat/build/build_id

Added to every build with the -b value; empty when -b is omitted.

download_file in the common build

Replaced by one entry per partition with a filename, then gpt_mainN.bin and gpt_backupN.bin per LUN.

partition_file, partition_patch_file in the common build

Replaced by rawprogramN.xml and patchN.xml per LUN.

Data files¶

  • filesystem-partition-names.list: one partition name per line, # comments allowed. gen_udev_rules writes no raw rule for these names, so their filesystems are still probed.

  • 55-qcom-raw-partitions-noblkid.rules.in: udev rules template whose single @QCOM_RAW_PARTITION_RULES@ line becomes one rule per raw partition name; its comments explain each rule.

Run tests/unit with the checkout on sys.path.

degpt/Cargo.toml builds the degpt crate (edition 2021) with the gpt 3.1 and uuid 1.8 crates; Cargo.lock pins them.

Repository settings¶

  • .github/workflows/build.yml: on pull requests and pushes to main, runs lint, unit tests, the platform build, integration and checksum checks, the checksum-manifest freshness check, and cargo build.

  • .github/workflows/quic-organization-repolinter.yml: on every push and pull request, checks licence, README, and source-header rules.

  • .github/workflows/documentation.yml: on pull requests and pushes to main, runs the documentation setup and check targets.

  • .github/CODEOWNERS: its comment explains the default reviewers.

  • .gitignore and degpt/.gitignore: keep generated platform output, Python and Rust build output, and documentation caches out of Git.
